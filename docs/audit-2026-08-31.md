## 🔴 Fixed: correctness

1. **Seeded probe leaked into the training RNG stream** (found first, fixed
   at `3cb9196` before the rest of the pass). `torch.manual_seed(probe_seed)`
   at every analysis event restarted the run's training randomness from a
   constant. Fix: `_probe_rng` save/restore (torch CPU + all CUDA generators,
   numpy). Era + impact: docs/invalid-runs.md top entry. Gated:
   `tests/test_spatial_eval.py::test_seeded_probe_leaves_the_training_streams_untouched`
   plus a CUDA-leg test.
2. **The probe's surviving sibling: `pN.state`/`pN.phase`.** The on-policy
   probe advances the net's own module-level state; at B=1 the next training
   rollout continued from the eval's leftovers. `_probe_rng` now snapshots
   and restores both, and `collect_pooled_activity(reset_each=True)` resets
   state per probe trajectory (seeded-probe protocol v2 - a measurement
   change, recorded in docs/invalid-runs.md).
3. **Thread-vs-capture race.** The prepare-resets worker thread started
   before `rollout_graph.prepare()`; CUDA graph capture with
   `capture_error_mode="global"` forbids concurrent CUDA work from any
   thread, so the worker's H2D uploads could land mid-capture
   (timing-dependent crash). Thread start moved after capture
   (`rl/collect/collector.py`). A worker crash also surfaces at join -
   gated by `tests/test_fast_reset.py::test_prepare_thread_error_surfaces`.
4. **Stream-0 bank-build reseed.** Multienv pool construction called
   `reset(seed=0)` on stream 0's LIVE wrapper, leaving its generator in the
   seed-0 state whatever `run.seed` was. Fixed with a deepcopy scratch
   (`envs/vector.py::_collect_layout_banks`), gated by
   `test_fast_reset.py::test_run_seed_reaches_stream_zero` - **verified to
   fail on the pre-fix code** (the naive draw-comparison gate did NOT fire,
   because the run-seeded room schedule masks the coupling; the gate reads
   the generator state itself). Impact wording in docs/invalid-runs.md.
5. **`raw` arm of `slurm/multienv.sh` silently whitened.** After whitening
   became the preset default, `norm=raw` emitted no flag - a "raw" run would
   have trained whitened with nothing failing. `raw` now passes
   `--train-policy.no-normalize-advantage`.
6. **Three homes for pixel→class.** The fork's `predCE`, the adapter's
   curiosity reduction, and `error_decomposition` each spelled the vocab
   lookup. Now one home: `predCE.targets_for` (fork `1939006e`); the adapter
   and the reward path call it, keeping the closed-set assert live on the
   reward side even under CUDA graphs (plus a periodic eager check inside
   `_GraphWMTrainer`, `_VOCAB_CHECK_EVERY=64`, since replays run no Python).
7. **`loop.py` trajectory-plot block** ran the plot for RANDOM runs through
   a rebuilt AC agent and outside `eval_mode`; fixed (random runs plot the
   random agent; `eval_mode` + `on_device` wrap it). A missing `eval_mode`
   import - my own error during the fix - was caught before commit.
