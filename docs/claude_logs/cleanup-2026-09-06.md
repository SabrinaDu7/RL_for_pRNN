### 4. Offline tools read the run's own config - (this commit)

Audit C9 and C11, plus C10's tail. Every offline tool that scores a checkpoint
built its own `Config` from flags: `checkpoint_series.run_config` could not
say `positions` at all (an 8-room run scored as rooms 0..4, silently);
`surprisal_timing.main` and `readout_probe.main` re-typed the preset, the
loss and the readout from flags, hard-coded `action_offset=0`, and passed
`--env.source.n` (which `Selected` no longer has, so both were broken by
cleanup 3 until this step); `prediction_figures.plot_run_predictions` rebuilt
the config from the recorded `argv` - which is the REQUESTED config, and is
the launching program's argv, not the training command's, whenever training
is driven in-process (every fingerprint run records the harness's argv).

The record that was already there: `provenance.json["params"]["config"]` is
the EFFECTIVE config, written by `setup_run` after `setup_training` (so a
rounded hidden size is the recorded one), typed with `_type` tags. What was
missing was the inverse of `to_dict`. Now:

- `Config.from_dict` (`configs.py::_from_jsonable`, type-directed from the
  field annotations) inverts `to_dict`; every preset round-trips, and so does
  the production command line with positions, kept landmarks, a checkpoint
  `Path`, focal CE and the MLP readout (tests/test_configs.py).
- `Config.of_run(run_dir)` reads a training run's provenance and rebuilds its
  config. A field the record predates is read as its default and a field
  since removed is dropped - both printed by name, never silent. ONE record
  shape changed meaning rather than merely gaining or losing a field, and it
  is translated: pre-2026-09-06 `Selected` said "the first n" with
  `positions` null (`_current_shape`, tested against that exact shape).
- `utils/checkpoints.py::run_dir_of` maps a checkpoint file - rolling or
  archived under `checkpoints/` (`ARCHIVE_DIRNAME`, now one home with
  `training/loop.py`) - to the directory holding its provenance.
- `surprisal_timing.load_checkpoint` is the ONE loader both probe tools use:
  config from provenance, rooms through the same `resolve_layouts` the
  training loop uses, `action_offset` from the config. `--positions` is now
  an optional SUBSET of the run's own rooms (`rooms_at`; a position the run
  never trained on is an error), which is what the single-room floor in
  docs/focal-loss-2026-08-31.md needs. `--readout` is gone: the record says.
- `checkpoint_series.main` and `plot_run_predictions` use `Config.of_run`;
  the series keeps `--room/--source/--impassable` as the printed fallback for
  runs older than provenance (2026-08-25).
