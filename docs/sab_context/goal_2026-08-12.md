## Why a square room

Every hidden-state object-coding result in this project has been null, and the
mechanism established on 2026-08-11 was that the readout learns the object
~89% position-independently, so nothing location-specific ever has to be
learned. The compaction doc's top recommendation was the symmetric room: the
L-room has an L-shaped wall plus a triangle, a plus and an x, so the agent
localises from geometry alone and never needs the object.

`MiniGrid-SquareRoom-v0` (minigrid commit d9a0de6) removes all of it. A single
object is then the ONLY cue breaking the four-fold symmetry - the one design
where an object-coding cell is mechanistically required rather than permitted.

## The paradigm

From the primary source (Tsao, Moser & Moser 2013, Curr Biol,
doi 10.1016/j.cub.2013.01.036), abstract quoted verbatim in the session log,
and `../experiment-curiousgeorge/docs/references/ref-trace-cells.png`:

    no object -> position 1 -> ... -> position 6 -> no object

The abstract's load-bearing sentence for the analysis:

> "Whereas some neurons fired at the objects, other cells developed specific
> firing at places where objects had been located on previous trials... The
> latter cells generally did not respond to the object when it was present,
> suggesting that object cells and object-trace cells are independent cell
> classes."

So the two are **separate populations**, and `throwaway/ported/moser/moser_analysis.py` tests
them separately:

| class | criterion |
|---|---|
| object cell at session k | field at the current position `P_k` |
| trace cell at session k | field at some earlier `P_j` (j<k, `P_j != P_k`), **and** no field at `P_k`, **and** no field at `P_j` in session 0 before any object existed |

"Field at c" = the unit's `field_gain` at c ranks above the 95th percentile of
that same unit's gains over all walkable cells, so chance is 5% by
construction and the population test is binomial against 0.05. This is the
metric validated earlier in the project (negative control 0.0601 p=0.174,
positive control 100% recall).

One disanalogy worth remembering: the paper's LEC cells show *little* spatial
modulation in an empty field, whereas these pRNN units are strongly spatial
(mean SI ~0.9). They are more like place cells than LEC cells.

## What was run

previous one's checkpoint, so weights, both optimizers and the frame counter
carry over while the environment changes. `rl.episodes_total` is cumulative

`batched_wm=false` (serial - the sweep on 2026-08-11 showed pooling loses),
seed 1, wandb on.

## What I expected, and what would change the conclusion

The honest prior is still **null**: nine previous designs failed, and the
readout-generalisation mechanism explains why. What is different here is that
the symmetry removal attacks that mechanism directly rather than adding
pressure around it.

The result that would matter is object cells clearly above 5% during object
sessions, with the peak FOLLOWING the object across positions - the control
that killed the earlier occlusion false positive. A trace result needs fields
persisting at departed positions into session 7.

If object cells appear but the peak does not follow the object, it is drift,
not coding. That check is `fig_moser_gain.png` plus the per-session columns of
`fig_moser_panel.png`.

## Trace cells: NULL — and I reported this wrong first

Raw counts rise monotonically to **17.0% at session 7 (p<1e-4)**, which looks
like a strong result. It is not. The trace criterion is a cumulative OR over
all previously-used positions, so the number of chances GROWS with session
index (1 at s2, 6 at s7). The correct analytic null is `1-0.95^n`, and against
it every count is BELOW chance.

The decisive control, run afterwards: the identical criterion applied to six
positions the object NEVER occupied, 400 random draws.

| session | #prev | observed | empirical null | p |
|---|---|---|---|---|
| 2 | 1 | 2.0% | 3.7% | 0.70 |
| 3 | 2 | 3.2% | 6.6% | 0.89 |
| 4 | 3 | 5.0% | 10.6% | 0.92 |
| 5 | 4 | 10.2% | 12.1% | 0.64 |
| 6 | 5 | 9.2% | 15.4% | 0.91 |
| 7 | 6 | 17.0% | 20.3% | 0.81 |

The null reproduces the entire rising pattern with no object ever present.
**The "trace cells" are counting chances, not traces.**

## Why the symmetric room did not bind — the actual finding

I briefly claimed sRSA rising 0.036 (session 0) -> 0.60 showed the object doing
the disambiguating work. **Retracted**: sessions are cumulative training
(8k -> 22k gradient steps), so that rise is training length.

The clean test is decoding the agent's QUADRANT from `h`. In a four-fold
symmetric room this should be at chance (0.25) unless something breaks the
symmetry, and the object is the only candidate. Trajectory-level CV, so no
within-trajectory leakage:

| session | object | with object | without object | delta |
|---|---|---|---|---|
| 1 | (5,4) | 0.806 | 0.805 | +0.001 |
| 2 | (10,6) | 0.838 | 0.838 | +0.000 |
| 3 | (6,11) | 0.830 | 0.832 | -0.002 |
| 4 | (12,3) | 0.848 | 0.845 | +0.003 |
| 5 | (3,9) | 0.846 | 0.847 | -0.001 |
| 6 | (11,12) | 0.828 | 0.827 | +0.001 |

**The hidden state localises to ~84% with NO object at all**, and the object
adds nothing (delta ~0.000 everywhere).

And the room really is symmetric — checked directly in observation space, six
(cell, heading) pairs against their 90-degree-rotated equivalents, max|obs
diff| = 0 for all six.

So position information is reaching `h` by a route that does not pass through
the visual scene. The remaining candidate is trajectory history: each probe
trajectory starts from a fixed cell with a fixed initial hidden state, and the
net integrates from there. Removing visual landmarks does not remove that.

**This is the lead.** Nine designs have now failed, and this is the first one
that says specifically WHAT to remove: not a visual cue, but the path-integration
route.

## Next design, and why

Break the history route, not the visual one:

1. **Teleport the agent mid-episode.** A relocation invalidates dead reckoning,
   so re-localisation must come from what is visible. This is the standard
   manipulation for forcing landmark use and it is a small env change.
2. **Randomise the initial hidden state per trajectory**, so `h` cannot encode
   "displacement from a known start".
3. Only then does "the object is the only disambiguating cue" actually hold.

A cheap first check before building anything: re-run the quadrant decode on
trajectories whose START cell is randomised and unknown to the decoder. If
accuracy collapses toward 0.25, trajectory history is confirmed as the route.
